## 用户需求

为对话信息增加结构化日志元数据，而非仅存储对话内容。

## 产品概述

在现有会话存储（sessions.json 的 messages 数组）基础上，为每条消息附加元数据（时间戳、使用的模型、token 数、耗时、状态等），仍保存在会话内部。同时新增一个「对话日志」入口，供用户在界面查看每个会话的详细日志信息；对话流本身不展示这些元数据。

## 核心功能

- 后端在对话流式响应结束时，通过 SSE 回流本次对话的元数据（模型名、token 数、耗时、状态）。
- 前端在落盘消息时，为每条消息附加 metadata 字段（用户消息记录发送时间；助手消息回填模型、token、耗时、状态、时间）。
- 新增「对话日志」入口（设置页或会话侧边栏），以表格/列表形式展示当前会话各消息的元数据详情。
- 兼容历史会话数据：旧消息无 metadata 时优雅兜底，不报错。

## 技术栈

- 前端：Vue 3（`<script setup>`）+ Ant Design Vue（antdv）+ Vite
- 后端：Node.js + Express（SSE 流式）
- 存储：本地 JSON 文件 `sessions.json`（沿用现有 `server/sessions.js` 模块）
- 模型调用：LangChain `@langchain/core` 的 `chatModel.stream` 与 `runAgent` 工具循环

## 实现方案

### 总体策略

在既有「前端 push 消息 → streamChat 解析 SSE → 后端 /api/chat 流式输出」链路上，增加「元数据回流」与「消息带 metadata 落盘」两段能力，并新增独立查看入口。完全复用现有会话存储与接口，不引入新存储格式。

### 关键技术决策

1. **后端元数据回流**：在 `/api/chat` 两条路径（有项目 `runAgent`、无项目 `chatModel.stream`）中，于响应开始前记录 `startTime=Date.now()`，结束时计算 `durationMs`；模型名取 `cfg.model || DEFAULT_MODEL`；token 数通过 LangChain `CallbackHandler`（监听 `LLMEnd` 累计 `usage`）在流式调用时采集。最后向 SSE 写入一条 `data: {"type":"meta","model":...,"tokens":...,"durationMs":...,"status":"ok"}` 事件，再写 `[DONE]`。

- 权衡：token 真实用量优先用 callback 统计；若 provider 不返回 usage（如部分兼容端点），token 兜底为 `null` 并在前端显示「未知」，避免伪造数据。

2. **前端 SSE 解析**：`src/api/agent.js` 的 `streamChat` 识别 `json.type === 'meta'` 事件，将其作为 `onDone(metadata)` 的入参（保持原有 `onDelta` 不变）；无 meta 事件时 `onDone()` 仍按旧行为触发（向后兼容）。
3. **消息 metadata 落盘**：`ChatPanel.vue` 中

- 用户消息：`session.messages.push({ role:'user', content:text, metadata:{ timestamp:Date.now() } })`
- 助手消息：初始化 `assistant = reactive({ role:'assistant', content:'', metadata:{} })`；`onDone(meta)` 时 `assistant.metadata = { timestamp:..., model:meta?.model, tokens:meta?.tokens, durationMs:meta?.durationMs, status:meta?.status || 'ok' }`
- `updateSession` 调用不变，metadata 随 messages 一起写入 `sessions.json`。

4. **「对话日志」入口**：在设置页（`SettingsPanel.vue`）新增「对话日志」Tab/抽屉，或在会话侧边栏（`App.vue`）的会话项增加「查看日志」按钮，打开 `a-drawer` 展示当前会话 `messages` 的元数据表格（列：时间、角色、模型、Token、耗时、状态）。对话流渲染（`ChatPanel.vue` 的 `msg__content`）不读取 metadata，保持不可见。
5. **兼容性**：所有读取 metadata 处均使用可选链 `m.metadata?.xxx` 兜底，旧会话（无 metadata 字段）显示「无日志信息」。

### 性能与可靠性

- 后端 metadata 事件仅在 `[DONE]` 前追加一条，开销可忽略；token 统计使用 LangChain callback，不额外请求。
- 前端不增加额外渲染负担（metadata 不参与对话流 diff）。
- 落盘仍走现有 `updateSession` 的整会话覆盖写，无新增 IO 路径。

## 实现注意事项

- 后端改动需重启 node server（沿用约定）；前端刷新页面生效。
- `runAgent` 当前无 token 统计，需在其流式循环内接入同一个 `CallbackHandler`，并通过参数把累计 token 回传给 `/api/chat` 写入 meta 事件（建议将 `res` 与 `usageRef` 一并传入，或让 `runAgent` 返回 `{usage}`）。
- 保持 `sessions.json` 旧数据可直接加载（无 metadata 不报错）。

## 关键代码结构（消息 metadata 约定）

```js
// 每条消息结构（向后兼容旧 {role,content}）
{
  role: 'user' | 'assistant',
  content: string,
  metadata?: {
    timestamp?: number,   // 消息产生时间
    model?: string,       // 助手消息使用的模型
    tokens?: number|null, // 本次回复 token 用量
    durationMs?: number,  // 本次回复耗时
    status?: 'ok' | 'error'
  }
}

// 后端 SSE meta 事件
{ type: 'meta', model: string, tokens: number|null, durationMs: number, status: 'ok'|'error' }
```
